# 🚀 Deploying CogniGuard (Frontend + Backend)

CogniGuard is a **two-part** application:

| Part       | Tech         | Hosted on  | Why                                                                                          |
|------------|--------------|------------|----------------------------------------------------------------------------------------------|
| `frontend` | Next.js 14   | **Vercel** | Vercel is perfect for Next.js static/SSR sites.                                              |
| `backend`  | Python Flask | **Render** | Your Flask app needs a *long-running process*, a writable filesystem (`data/store.json`, `uploads/`, `exports/`), and heavy ML libraries — none of which work on Vercel serverless functions. |

> ⚠️ **Why only the frontend works right now:** `frontend/src/lib/api.ts` hard-coded the API URL as `http://127.0.0.1:5000` (your own computer). Visitors' browsers tried to reach *localhost* and failed on every API call (login, register, tests, reports…). This guide fixes that by making the backend URL configurable and deploying the backend to a real Python host.

## Step 2 — Deploy the backend to Render (free)

1. Go to **https://dashboard.render.com** and create a free account (GitHub sign-in).
2. Click **New + → Blueprint** (or *New Blueprint Instance*).
3. Select your repository **`Sridharshini12345/Dementia_screening`**.
   Render detects `Cogniguard/backend/render.yaml` automatically.
4. Click **Apply / Create resources** and wait for the build to finish
   (a few minutes — the log shows `pip install -r requirements-prod.txt` then gunicorn starting).
5. When the service turns **Live**, open `https://cogniguard-api.onrender.com/api/health`
   in your browser. You should see `{"status":"healthy"}`.
6. Open the Render **Environment** tab and set any optional values
   (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM_EMAIL`) for emailed reports.
   Confirm `PUBLIC_BASE_URL` matches your Render URL.

---

## Step 3 — Point the Vercel frontend at the rendered backend

1. Open **https://vercel.com**, go to your CogniGuard project.
2. Click **Settings → Environment Variables**.
3. Add:
   - **Key:** `NEXT_PUBLIC_API_BASE`
   - **Value:** `https://cogniguard-api.onrender.com`
   - **Environments:** Production (and Preview if you want).
4. Go to **Deployments → Redeploy** the latest deployment (or push a new commit).
   `NEXT_PUBLIC_*` variables are baked in at build time, so a redeploy is required.

### Verify your Vercel Root Directory setting (if pages 404)

This repo has the app inside a `Cogniguard/` folder, so in Vercel **Settings → General** the
**Root Directory** should be `Cogniguard/frontend`. If your frontend renders already, this is set.

---

## Step 4 — Smoke test the full stack

1. Open your Vercel site.
2. **Register** a new user → you should reach the profile/questionnaire page
   (before, this failed with a network error because it called localhost).
3. Log in (**Admin demo:** `admin@cogniguard.local` / `cogni@123`).
4. Run a test round → **Results** page shows the risk score.
5. Open **Reports** → download a PDF (generated by the backend).
6. Check **Admin → ML Status** shows the model endpoints reachable.

If anything fails, open your browser DevTools **Network** tab:
- A failed request to `localhost:5000` means the frontend bundle still has the old URL → redo Step 3 and hard-refresh (Ctrl+F5).
- A failed request to `cogniguard-api.onrender.com` → check the Render logs (service → **Logs** tab).

## Optional — Alternative backend hosts

Anything that runs a Docker image or a Python WSGI server works:

- **Railway** (`railway.app`) — `railway up`; `PORT` is set automatically.
- **Fly.io** (`fly.io`) — uses the existing `backend/Dockerfile`; the updated `app.py` honors `HOST`/`PORT` env vars.
- **Hugging Face Spaces (Docker)** — copy the `backend/` folder, expose port `7860` (set `PORT=7860`).

For all of them the frontend step is identical: set `NEXT_PUBLIC_API_BASE` to the new backend URL and rebuild on Vercel.

## Data & persistence notes

The backend stores data in the JSON file `backend/data/store.json` (with `uploads/` and `exports/`).
On free Render, the service disk is **ephemeral** — data survives restarts but is reset on redeploy.
For a real deployment, attach a **persistent disk** (Render Disks, paid) or move to a database
(out of scope for this version). The admin user is auto-created on first launch by `backend/store.py`.

## Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| Frontend loads but actions fail; Network tab shows `localhost:5000` | `NEXT_PUBLIC_API_BASE` not set/redeployed on Vercel (Step 3). |
| `cogniguard-api.onrender.com/api/health` doesn't load | Build failed; check Render build log. Common: repo path misspelled in `rootDir`. |
| Build fails on `pip install` | Try without optional ML extras (commented out in `requirements-prod.txt`). |
| CORS error in browser console | Should not happen (`CORS(app)` allows all origins), but ensure no stray origin filter. |
| Reports PDF download 404s | `PUBLIC_BASE_URL` on Render must match the actual service URL (it is used to build share links). |
> ✏️ **If `cogniguard-api` is already taken as a Render name**, edit `PUBLIC_BASE_URL` in the
> Render Environment tab so it points to your *actual* service URL (e.g. `https://cogniguard-api-abc123.onrender.com`).

> ℹ️ **Free-tier notes:** Render free web services pause after ~15 min of inactivity and take
> ~30–60 s to wake up on the next request. For demos/vivas that's usually fine. A tiny uptime
> pinger (UptimeRobot) can keep it warm.

### Manual alternative (no Blueprint)

If Blueprint setup gives you trouble, create the service manually:

1. **Dashboard → New + → Web Service → select the repo.**
2. **Root Directory:** `Cogniguard/backend`
3. **Runtime:** Python 3
4. **Build Command:** `pip install -r requirements-prod.txt`
5. **Start Command:** `gunicorn app:app --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 120`
6. **Health Check Path:** `/api/health`
7. Click **Create Web Service**, then add env vars afterwards.
